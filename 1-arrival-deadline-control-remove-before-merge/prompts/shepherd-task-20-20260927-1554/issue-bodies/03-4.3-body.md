Resolved decisions: create a serializable CDI `@Named @ViewScoped` editor bean. It must load only through `BookingServiceFacade.loadCargoForRouting(trackingId)`, retain the `CargoRoute`, and parse the DTO date into `java.util.Date` with a per-load `SimpleDateFormat("MM/dd/yyyy")`. The plan records that the full formatted deadline begins with that date portion, yielding the same calendar date shown by the table. Do not introduce a shared mutable formatter or access domain/repository types.

A malformed deadline must surface a clear application/view error rather than becoming null or merely printing a stack trace. A null selected date must be rejected, but no future-date, old-deadline, or itinerary chronology rule may be invented. Successful submission delegates through the facade and closes with `"DONE"`; a failed facade call must not close the dialog.

## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDate.java`

Use this required shape:

```java
@Named
@ViewScoped
public class ChangeArrivalDeadlineDate implements Serializable {
    private static final long serialVersionUID = 1L;

    private String trackingId;
    private CargoRoute cargo;
    private Date arrivalDeadlineDate;

    @Inject
    private BookingServiceFacade bookingServiceFacade;
}
```

Provide:

- `getTrackingId()` and `setTrackingId(String)`;
- `getCargo()`;
- `getArrivalDeadlineDate()` and `setArrivalDeadlineDate(Date)`;
- `load()`;
- `changeArrivalDeadline()`.

`load()` must:

1. Call `bookingServiceFacade.loadCargoForRouting(trackingId)`.
2. Retain the returned `CargoRoute`.
3. Create a new `SimpleDateFormat("MM/dd/yyyy")` for that load.
4. Parse the DTO's displayed date representation into `arrivalDeadlineDate`.
5. Surface parsing failure using a clear repository-consistent application/view error.

`changeArrivalDeadline()` must:

1. Reject a null selected date with normal JSF validation or explicit bean validation.
2. Invoke `bookingServiceFacade.changeDeadline(trackingId, arrivalDeadlineDate)`.
3. Only after successful return, call `PrimeFaces.current().dialog().closeDynamic("DONE")`.
4. Propagate or visibly report facade failure without closing.

Add a focused container-free JUnit test if practical using a hand-written facade fake. Cover the correct tracking ID on load, `MM/dd/yyyy` conversion, exact submit delegation, malformed DTO data, and null selected date. Do not add a mocking library.

## Completion gates

- `./mvnw clean package -Popenliberty` succeeds on JDK 17.
- The bean is serializable and uses the established CDI `@Named` and JSF `@ViewScoped` annotations.
- The bean imports facade APIs/DTOs but no cargo domain or repository classes.
- Parsing uses no static/shared mutable `SimpleDateFormat`.
- Malformed DTO data and null input have explicit failure behavior.
- The dialog closes only after successful facade delegation.
- No launcher class or XHTML is added in this task.

## Out of scope

- Dynamic-dialog launcher behavior or session-scoped managed beans.
- Dialog XHTML and dashboard-table changes.
- Repository or domain access from the web layer.
- Changing `CargoRoute` to add a `Date` property.
- New request DTOs or formatted-string facade parameters.
- New chronological business rules.
- Mocking dependencies, Arquillian modernization, or unrelated framework/configuration changes.
